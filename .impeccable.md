## Design Context

### Users
MVZ (multi-location medical center) managers, site managers, and medical directors in Germany. They use the system on desktop workstations (24" monitors, 1920×1080) during their workday to monitor operational KPIs, identify patterns, and make staffing/scheduling decisions. Their job: maintain efficient operations across multiple clinic locations while staying compliant with German healthcare regulations. They are busy professionals who need to extract insights quickly and get back to managing their facilities.

### Brand Personality
**Modern, Intelligent, Calm.**

The interface should feel like a precision instrument — smart and data-driven without being overwhelming. It conveys authority through clarity, not decoration. Every element earns its place. The system speaks with quiet confidence: it knows what matters and surfaces it without noise.

**Emotional goals:** Confidence & control ("I see the full picture"), trust & reliability ("this data is accurate and compliant"), efficiency & focus ("I found what I need in seconds").

### Aesthetic Direction

**Visual tone:** Clean, minimal, information-dense but never cluttered. Professional without being sterile. The dark blue nav rail (#00077B) anchors the brand; the content area stays light and airy with purposeful use of the traffic-light status palette.

**References:**
- **Linear / Notion** — Clean information density, fast feel, minimal chrome
- **Stripe Dashboard** — Polished data visualization, clear visual hierarchy, professional confidence
- **German institutional portals** — Conservative trustworthiness, compliance-appropriate gravitas

**Anti-references (explicitly avoid):**
- Flashy SaaS / startup aesthetics — no gratuitous gradients, bouncy animations, playful illustrations, or trendy visual gimmicks
- Legacy enterprise / SAP — no dense gray grids, tiny unreadable fonts, or 2000s-era UI patterns
- Consumer health / wellness apps — no gamification, pastel-rounded mobile aesthetics, or casual wellness vibes

**Theme:** Light mode only. White backgrounds with the established gray-blue text palette. Status colors (red/orange/green/gray) provide the primary visual accents.

### Accessibility
**WCAG 2.1 AAA compliance** is the target. This means:
- Enhanced contrast ratios (7:1 for normal text, 4.5:1 for large text)
- No content that relies solely on color — always pair with shape, icon, or text label (already practiced with traffic-light status dots)
- Full keyboard navigability with visible focus indicators
- Screen reader support with proper ARIA labels and semantic HTML
- No time-limited interactions
- Reduced motion support via `prefers-reduced-motion` media query
- Text resizable to 200% without loss of content or function

### Design Principles

1. **Signal over noise** — Lead with status and insight, not raw data. Every visual element must answer "so what?" before "what." KPI cards show red/yellow/green before showing numbers.

2. **Progressive disclosure** — Three-level hierarchy: scan (KPI cards) → understand (charts) → act (detail tables). Never dump everything at once. Every click deepens context; back navigation restores state exactly.

3. **Quiet confidence** — The interface should feel authoritative through precision, not decoration. Minimal shadows, restrained color, consistent spacing. No element draws attention unless it has earned it through informational importance.

4. **Compliant by design** — Decision support only, never auto-execution. External/read-only data visually distinct from editable data. Practitioner data anonymized by default. Rules and thresholds always visible. These aren't just features — they're design constraints that build trust.

5. **Density with clarity** — Desktop-first means we can show more, but density must serve comprehension. Use whitespace as a structural tool (16px within sections, 24px between sections). Typography hierarchy (weight + size + color) does the work that borders and boxes would in lesser designs.
