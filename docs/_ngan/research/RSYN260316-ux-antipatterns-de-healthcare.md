# UX/UI Anti-Patterns in German Healthcare Software (PVS/KIS/MVZ)

Research synthesis of usability anti-patterns specifically relevant to the German healthcare IT market and CorePVS product context.

## Anti-Pattern Table

| # | Anti-Pattern | Why It Fails in German Healthcare / MVZ | Better Pattern | Source |
|---|---|---|---|---|
| | **— CorePVS Product Principles (derived from product context)** | | | |
| 1 | **Auto-Execution Without Confirmation** | Contradicts the core "decision support, not automation" principle. In healthcare, automatic actions on billing submissions, prescription signing, or Schein state changes carry legal and financial consequences. Especially dangerous in MVZ where actions can propagate across locations. | System suggests next steps but never auto-executes. Dashboard recommends rebalancing capacity; user decides. All state-changing actions require explicit confirmation proportional to their impact. | `product-context.md:64` (Solution: "Decision support, not automation"), `product-context.md:256-257` (UX Principle: "Decision support, not automation") |
| 2 | **Ambiguous Edit States** | If read-only vs. editable isn't instantly clear, external hospital data (e.g., HIS referral records) could be accidentally modified. This is both a UX failure and a legal risk — external data is legally independent from own documentation. In MVZ with cross-location data sharing, ambiguity multiplies. | Clear visual separation: external vs. own data. External data is read-only and visually highlighted. Own documentation is editable and legally independent. Use distinct visual treatments (background color, lock icons, border styles) that are parseable at a glance. | `product-context.md:253-254` (UX Principle: "Clear visual separation: external vs. own data"), `product-context.md:227-228` (UX Axis: "Safety / Clarity") |
| 3 | **Generic Error Messages** | "Something went wrong" is useless when an MFA needs to fix a rejected KV billing submission, a failed E-Rezept signing, or a VSDM timeout. German healthcare workflows have specific, recoverable error states — generic messages prevent recovery and waste time. | Domain-specific, actionable error messages. "Schein 0101 missing ICD for GOP 01100 — add diagnosis to continue." Include the affected entity, what's wrong, and how to fix it. | `product-context.md:259-260` (UX Principle: "All states for every screen"), `product-context.md:227-228` (UX Axis: "Safety / Clarity"), `product-context.md:105-106` (MFA: Billing submission tasks) |
| | **— German Healthcare Market (research-backed)** | | | |
| 4 | **Certification-Driven UI (KBV-Compliance-First Design)** | KBV certification (KVDT) tests only billing correctness and data format compliance, not usability. PVS vendors optimize screens around what passes KBV/KV audit checks rather than clinical workflow. This produces forms that mirror KVDT field structures (Feldkennungen) instead of how MFA or physicians actually think about a patient encounter. The Zi survey of 10,245 evaluations confirmed that widely-used KBV-certified systems receive markedly negative usability ratings. | Design for the clinical encounter first, then map to KVDT fields in the data layer. Certification compliance should be an export/validation concern, not the UI organizing principle. | Zi PVS Survey; KBV Anforderungskatalog |
| 5 | **Schein-Centric Navigation** | German ambulatory billing revolves around the Abrechnungsschein (billing case per quarter per Kassenart). Many PVS systems force users to think in Schein/quarter terms when documenting care. Clinicians must first select the correct Schein before they can document, leading to wrong-Schein errors, especially in MVZ settings with multiple Fachrichtungen and Betriebsstaetten sharing one system. | Patient-centric navigation with automatic Schein resolution. The system should infer the correct Schein from context (treating physician's Fachgruppe, Betriebsstaette, patient insurance type, quarter) and only surface Schein selection when ambiguous. | Zi PVS Survey; Healthcare-Digital |
| 6 | **TI-Error-Wall (Telematik Infrastructure Failure Flooding)** | The Konnektor, eGK card terminal, and TI backend produce cryptic error codes (VSDM errors, PIN failures, connectivity drops). 62.4% of practices report connector problems (Zi survey). PVS systems surface raw TI/Konnektor error codes directly to MFA staff without actionable guidance, blocking the check-in workflow entirely. | Graceful degradation with plain-language error recovery. When VSDM fails, offer offline Ersatzverfahren automatically. Translate Konnektor error codes into actionable steps ("Card reader disconnected — check USB cable at reception desk 2"). Queue failed TI operations for background retry. | Zi PVS Survey; Apotheke ADHOC; Coliquio |
| 7 | **Undifferentiated Alert Fatigue (Warnungsüberschwemmung)** | German PVS/KIS systems layer multiple alert sources: Arzneimittelinteraktionen (ABDA database), Priscus-Liste warnings for elderly patients, BtM-Rezept requirements, Heilmittelverordnung budget warnings (Wirtschaftlichkeitsprüfung), ICD plausibility checks. AHRQ research shows 49-96% of clinical alerts are overridden. In German practice, Regress anxiety compounds this: physicians dismiss all alerts because they cannot distinguish budget warnings from safety-critical drug interactions. | Severity-tiered, role-tailored alerts. Hard-stop only for critical interactions (ABDA severity "schwerwiegend"). Surface Wirtschaftlichkeit/budget warnings separately in a non-blocking dashboard. Suppress alerts already acknowledged for ongoing medications (Dauermedikation). | AHRQ PSNet; PMC Alert Fatigue |
| 8 | **Modal-Dialog Gauntlet** | Creating an E-Rezept requires multiple sequential confirmations: drug selection, dosage, Dosieranweisung text, BtM check, insurance coverage check, HBA PIN entry, and TI signing. Many PVS systems implement each step as a blocking modal dialog, turning a 15-second paper Rezept into a 45-second click-through ordeal. More broadly, opening modal dialogs for every action breaks workflow and makes it impossible to compare data across contexts — critical when MFA needs to cross-reference patient/insurance data. | Inline progressive disclosure. Show details in a single composable view. Use smart defaults. Batch-sign multiple E-Rezepte with one HBA PIN entry per session. Reserve modals only for true safety gates. Prefer inline editing or side panels for non-blocking interactions. | gematik TI-Score; Heise |
| 9 | **Context-Blind Quartalsabrechnung** | Quarterly billing (Quartalsabrechnung) involves Schein completeness check, ICD-10-GM assignment, EBM/GOÄ Ziffer validation, KBV Prüfmodul execution, and KVDT export. PVS systems often present this as a monolithic end-of-quarter batch job with hundreds of undifferentiated error messages, forcing MFA to fix errors they no longer remember from weeks earlier. | Continuous inline validation throughout the quarter. Flag incomplete Scheine and missing ICD codes at the point of care (end of encounter), not end of quarter. Provide a filtered, prioritized Abrechnung dashboard that groups issues by severity and affected Schein. | Zi PVS Survey; KBV Anforderungskatalog |
| 10 | **One-Size-Fits-All MVZ Interface** | MVZ combine multiple specialties (Fachrichtungen) under one legal entity. Most PVS systems offer a single interface regardless of whether the user is a Hausarzt, Kardiologe, or Psychotherapeut, each of whom has radically different documentation needs, EBM Ziffern, and workflow rhythms. This forces specialists into generic screens bloated with irrelevant fields. | Role-and-specialty-adaptive workspaces. Each Fachrichtung gets a tailored default view with relevant Ziffernketten, documentation templates (Befundvorlagen), and order sets. Shared patient data remains unified underneath, but the working surface adapts to clinical context. | Zi PVS Survey; Deutsches Ärzteblatt |
| 11 | **eGK-Before-Everything Gate** | Many PVS systems require a successful eGK read (VSDM) before any clinical workflow can begin. When the card reader fails, the TI is down, or the patient forgot their eGK, the entire check-in and documentation workflow is blocked. | Decouple clinical workflow from insurance verification. Allow encounter creation with provisional patient data (Ersatzverfahren), then reconcile insurance data asynchronously when the eGK is available. Never block clinical documentation on an administrative dependency. | Zi PVS Survey (62.4%); Apotheke ADHOC; Coliquio |
| 12 | **Copy-Paste Documentation (Befund-Klonen)** | To save time in systems with poor templating, physicians copy-paste previous Befunde and Arztbriefe, creating "note bloat" with outdated findings carried forward. Especially dangerous in MVZ handoffs between providers. German liability law (Dokumentationspflicht) makes inaccurate carried-forward findings a legal risk. | Structured smart templates with explicit "changed/unchanged" markers. Provide Befund templates that pull forward prior values but require active confirmation. Highlight what has changed since last visit. | NNGroup Medical Usability; AMA Health IT |
| 13 | **Hidden Workflow State (Unsichtbarer Behandlungsstatus)** | A patient visit moves through implicit states: Anmeldung → Wartezimmer → Behandlungszimmer → Labor → Arzt → Abrechnung. Many PVS systems lack explicit workflow state visibility, forcing MFA to use paper lists, sticky notes, or shouting across hallways. In a multi-location MVZ, silent state changes can cause billing errors across locations. | Explicit patient flow board (digitale Wartezimmerliste) showing real-time status per patient, room assignment, and next required action. Color-coded states visible to all roles. Automatic state transitions triggered by clinical actions. | NNGroup Medical Usability |
| 14 | **Monolithic Patient Record** | German PVS systems often present the entire patient history — Diagnosen, Medikation, Laborwerte, Befunde, Abrechnungsdaten, Impfungen, AU-Bescheinigungen — in a single scrollable view or deeply nested tab structure. With long-term patients, finding relevant information becomes a needle-in-haystack exercise. Violates the Density UX axis — on a 24" monitor, primary actions and status must be visible without scrolling. | Context-sensitive record views. Default to a visit-focused summary showing today's relevant data (active diagnoses, current medications, recent labs, open orders). Provide specialty-specific lenses. Use progressive disclosure: summary first, full history on demand. | AMA Health IT; NNGroup Medical Usability |
| 15 | **Disconnected Formularverwaltung (Form Silo Pattern)** | German healthcare requires numerous official forms: AU-Bescheinigung (Muster 1), Überweisungsschein (Muster 6), Heilmittelverordnung (Muster 13/18), Krankenhauseinweisung (Muster 2), Laborüberweisung (Muster 10). PVS systems often implement each as an isolated form module requiring redundant re-entry of patient data, diagnoses, and physician details already present in the system. | Pre-populated, context-aware form generation. All Muster forms should auto-fill from the current encounter context (patient demographics, active ICD codes, treating physician LANR/BSNR). Expose form creation as actions within the clinical workflow, not as separate menu destinations. | Healthcare-Digital; Zi PVS Survey |

## Key Sources

- **Zi PVS Survey (2024)**: 10,245 evaluations across German practices showing strong correlation between error frequency and low usability scores. Widely-used PVS systems (e.g., CGM TURBOMED, CGM M1 PRO) scored worst; newer systems (tomedo, T2med) scored best.
- **gematik TI-Score**: Tracks E-Rezept software usability and acknowledges that user-oriented design is a central prerequisite for seamless E-Rezept workflows.
- **KBV Certification Scope**: Only tests billing compliance (KVDT format correctness), explicitly excludes usability and system stability due to lack of legal basis.
- **AHRQ/PSNet Alert Fatigue Research**: 49-96% override rates for clinical alerts; only ~7% of medication alerts found to be clinically appropriate.
- **Nielsen Norman Group — Medical Usability**: Field study identified 22 ways automated hospital systems can dispense wrong medication, primarily through classic usability failures.
- **AMA Statement on Health IT**: Called for improved design that reduces cognitive workload, noting health IT is "misaligned with cognitive and workflow requirements of medicine."
- **CorePVS Product Context**: Anti-patterns #1-3 derived from established product principles (decision support not automation, external vs. own data separation, density/clarity UX axes).
