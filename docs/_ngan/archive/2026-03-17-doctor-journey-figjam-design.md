# Doctor Hausarzt FigJam Journey Map Design

Date: 2026-03-17
Source: `docs/_ngan/JMAP260317-doctor-hausarzt.md`
Audience: Product and design team
Consumption mode: Async review
Scope: Doctor journey adapted into a FigJam User Journey Map template structure

## Goal

Create a FigJam board that converts the approved doctor journey map into an async-readable workshop artifact using the user's preferred FigJam User Journey Map template structure. The board should preserve the doctor journey narrative, make friction visible, and include inferred opportunity framing consistent with the requested template.

## Recommended Format

Use a template-style user journey map with:

- Horizontal phase timeline from left to right
- Fixed swimlanes for phase content categories
- Right-side opportunity clusters and key insight overlay

This matches the user's requested FigJam structure while staying grounded in the doctor journey source.

## Main Frame

- Title: `Doctor (Hausarzt) — MVZ Journey (As-Is)`
- Layout: horizontal timeline from left to right
- Context note: rotating doctor in MVZ, legacy PVS, 40-60 patients per day, 7-8 minutes per encounter

## Swimlanes

Top to bottom:

1. Phases
2. Actions
3. Touchpoints
4. Thoughts and Emotions
5. Pain Points
6. Opportunities

Color mapping:

- Phases: gray
- Actions: blue
- Touchpoints: purple
- Thoughts and Emotions: yellow
- Pain Points: red
- Opportunities: green

## Phase Columns

Use six phase columns:

1. Day Start and Preparation
2. Patient Intake and Handoff
3. Consultation and Clinical Assessment
4. Documentation and Treatment
5. Prescriptions, Referrals and Forms
6. Post-Visit and Day Close

Each column contains grouped stickies for each swimlane.

## Right-Side Layers

Add a right-side area containing:

- Opportunity clusters:
  - Operational Intelligence
  - MVZ Orchestration
  - Workflow Automation
  - Safety and Billing Accuracy
- Key insight overlay as a large sticky
- Optional severity legend for pain point tagging

## Content Rules

- Ground the board in the doctor journey markdown
- Keep wording concise enough for board readability while preserving the original meaning
- Adapt the content into the requested template structure rather than reproducing the markdown literally
- Infer opportunities from repeated pain points because the user explicitly requested the standard template pattern with an opportunities lane
- Keep the opportunity layer high-level and directional rather than fully solutioned

## Delivery

Create the board as a FigJam file using the available diagram workflow, optimized for async review and structured to mirror the requested FigJam User Journey Map template.
