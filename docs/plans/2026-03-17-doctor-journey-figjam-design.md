# Doctor Hausarzt FigJam Journey Map Design

Date: 2026-03-17
Source: `docs/_ngan/JMAP260317-doctor-hausarzt.md`
Audience: Product and design team
Consumption mode: Async review
Scope: Current-state doctor journey only

## Goal

Create a FigJam board that converts the approved doctor journey map into an async-readable workshop artifact. The board should preserve the current-state narrative, make friction visible, and avoid drifting into future-state solutioning.

## Recommended Format

Use a hybrid board structure:

- A matrix backbone for fast scanning across the full day
- Small callout annotations to preserve workshop-style richness

This balances overview and depth better than either a pure matrix or a pure storyboard.

## Board Structure

### Header

- Title: `Doctor (Hausarzt) Journey Map`
- Subtitle with context: MVZ, 2-3 locations, rotating doctor, legacy PVS
- Short scope note: `As-Is / current-state only`
- Short workload note: `~40-60 patients/day, ~7-8 min per encounter`

### Main Map

Six columns, one per phase:

1. Day Start & Preparation
2. Patient Intake & Handoff
3. Consultation & Clinical Assessment
4. Documentation & Treatment
5. Prescriptions, Referrals & Forms
6. Post-Visit & Day Close

Each phase contains five stacked layers:

1. Actions
2. Touchpoints
3. Thoughts & Emotions
4. Pain Points
5. Moment of Truth

### Workshop-Style Callouts

Add a limited number of visual callouts to highlight the most repeated or consequential current-state frictions, without introducing future-state ideas. Callouts should stay evidence-based and trace back to the source markdown.

### Footer

- Legend for content grouping/colors
- Source reference to the markdown artifact
- Version/date note

## Content Rules

- Stay tightly scoped to the doctor's current-state journey
- Do not add prioritized opportunities or solution concepts
- Keep wording concise enough for board readability while preserving the original meaning
- Prefer evidence-rich pain points and moments of truth over exhaustive narrative text

## Delivery

Create the board as a FigJam file using the available diagram workflow, optimized for async review rather than live facilitation.
